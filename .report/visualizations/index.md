# Каталог визуализаций — индекс

> Формат каждого файла техники — RFC-блоки (как `_terms.md`): `# [viz::TechniqueName]`, затем
> поля `Standard name / Class / Domain / Description / Sequence / Applicability / Limits /
> Source / Used in / Example`. `Sequence` описывает кадры словами (первый — проблема, последний —
> решение, промежуточные — преобразования); `Example` — тот же набор кадров РЕАЛЬНЫМ кодом
> (`css`/`html`/`js`), который навык вставляет без изменений в общий каркас страницы
> (`.claude/skills/visualize-approach/SKILL.md`) при сборке картинки. Без `Example` повторная
> сборка не гарантированно даёт ту же картинку — `Sequence` описывает идею, `Example` фиксирует
> конкретные числа/цвета/разметку. Сама картинка должна быть понятна БЕЗ текста — подписи в ней
> короткие символьные метки (`?`, `×2`, `=`), не предложения.

| Приём (стандартное название) | Когда применять | Файл |
|---|---|---|
| **Skip counting** (счёт прыжками по числовой прямой) | понять, что вообще входит в ответ, до вычислений | [skip-counting.md](skip-counting.md) |
| **Bar model / tape diagram** (Singapore Math) | в задаче есть «или» между двумя условиями, риск двойного счёта | [bar-model.md](bar-model.md) |
| **Gauss's trick** (парное сложение, «радуга») | нужно быстро сложить длинный ряд чисел с равным шагом | [gauss-pairing.md](gauss-pairing.md) |
| **Диаграмма Венна** (Venn diagram) | нужно увидеть пересечение двух условий одним взглядом | [venn.md](venn.md) |

## Дисциплина пополнения

Принципы, из которых выведены пункты ниже (и прецеденты их нарушения) —
`.claude/rules/visualization-principles.md`.

1. Новый приём — новый `.md`-файл в RFC-блоках, плюс строка в таблице выше.
2. Каждый файл открывается блоком `## [viz::Name]` со стандартными полями (см. пример выше).
   Поле `Sequence` обязательно и описывает кадры картинки от проблемы к решению. Поле `Example`
   обязательно и несёт реальный код тех же кадров — без него `Sequence` описывает только идею, а
   повторная сборка картинки не гарантированно совпадает с прошлой.
3. Тот же приём, применённый к новой задаче, НЕ создаёт новый файл — дописывается только строка
   `Used in:` в существующем `.md`.
4. Перед добавлением нового приёма — проверить поиском, есть ли у него устоявшееся название;
   `Standard name:` — ВСЕГДА стандартное название, а не придуманное под задачу.
5. Сама визуализация (не `.md`) обязана быть понятна без чтения текста: первый кадр — проблема,
   последний — решение, промежуточные — последовательность преобразований. Текст на картинке —
   только короткие символьные метки (номер шага, `×2`, `=`), не предложения.
6. Навык `.claude/skills/visualize-approach/SKILL.md` читает этот индекс первым шагом каждого
   вызова.
