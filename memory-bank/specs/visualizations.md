# Каталог визуализаций приёмов решения

## Vision
Человек без подготовки смотрит на картинку и, не читая текста, понимает, из какой проблемы в
какое решение приводит приём: первый кадр — что не так, последний — ответ, между ними — шаги.
Одна и та же просьба показать приём всегда даёт одну и ту же картинку — каталог, а не импровизация.

Источник требований — цикл правок 2026-09-01 на euler001 (ретро: 13 раундов, 5 точек
эскалации); каждое требование ниже привязано к раунду, в котором оно было нарушено.

## Термины
MUST/MUST NOT/SHALL/SHOULD/SHOULD NOT/MAY — как в RFC 2119. Термины домена — `_terms.md`,
контекст `viz`: [viz::Catalog](../_terms.md#vizcatalog), [viz::PageSkeleton](../_terms.md#vizpageskeleton), [viz::SkipCounting](../_terms.md#vizskipcounting),
[viz::BarModel](../_terms.md#vizbarmodel), [viz::GaussPairing](../_terms.md#vizgausspairing), [viz::VennDiagram](../_terms.md#vizvenndiagram),
[viz::BinarySearch](../_terms.md#vizbinarysearch), [viz::LadderMethod](../_terms.md#vizladdermethod).

## Скоуп
**В скоупе:** структура каталога `memory-bank/visualizations/` (каркас, код кадров, сборка,
результат) и блоков `[viz::*]` в `_terms.md`,
правила выбора формы приёма, структура кадров, привязка к подходам, детерминизм повторной
сборки, навык-сборщик `.claude/skills/visualize-approach/SKILL.md`.

**Вне скоупа:** сами математические подходы (см. [approaches](approaches.md)); приёмы ускорения вычислений
(`TRICKS.md`); публикация картинок в облако (сознательно отвергнута — сборка только локальная);
перевод каталога на английский (открытый вопрос владельца); сами задачи (условие, решение,
критерии корректности) — живут в `euler{NNN}/README.md`, не здесь (см. MUST-no-task-specifics).

## Находки, положенные в основу
- **F1** Карточки выбирались по наличию канонического названия, а не по понятности — дошло до
  Решета Эратосфена с перевёрнутой целью. Трассировка: MUST-form-before-name.
- **F2** Четыре раза подряд дефект картинки первым увидел владелец по скриншоту (дважды
  совпадение чисел 30/30, дважды съехавшие дуги); проверка сводилась к подсчёту тегов, координаты
  дуг считались из предположений о раскладке. Трассировка: MUST-render-observed,
  MUST-geometry-measured, MUST-distinct-step-numbers.
- **F3** Поле «когда применять» пересказывало параметры примера («одно-два небольших числа,
  короткий отрезок») вместо класса задач; после первого замечания исправлена одна карточка, а не
  принцип. Трассировка: MUST-applicability-is-class, MUST-fix-propagates.
- **F4** Один статичный кадр «решение» плюс абзацы прозы — переход от проблемы к ответу жил
  только в тексте («красиво, но непонятно, что к чему ведёт»). Трассировка: MUST-frame-sequence,
  MUST-symbolic-labels, MUST-text-in-spec.
- **F5** После переноса текстов в md там осталась только идея кадров; реальные числа и раскладка
  жили во временном файле — повтор не совпал бы. Трассировка: MUST-deterministic-rebuild,
  MUST-code-separate.
- **F6** Три редирект-заглушки со старых рабочих имён уехали в публичный репозиторий без единой
  входящей ссылки — выглядели как семь приёмов вместо четырёх. Трассировка: MUST-redirect-only-if-linked.
- **F7** Подходы и картинки существовали как два несвязанных списка. Трассировка:
  MUST-approach-link.
- **F8** (euler002) Второй раз подряд одна из двух половин решения (предвычисление списка) не
  получила своей визуализации — тот же класс, что F1's skip counting: подготовительный шаг, не
  отдельный приём. Подтверждает принцип 4/MUST-applicability-is-class с другой стороны — не
  каждая половина алгоритма заслуживает картинки, только то, что само по себе узнаваемая техника
  (здесь — бинарный поиск).
- **F9** (euler003) Перед выбором формы для пробного деления сравнили два стандартных варианта —
  вольное «факторное дерево» (любая пара множителей на каждом шаге) и «метод лесенки» (строго
  наименьший простой делитель, деление до тех пор, пока остаток сам не окажется простым).
  Выбрали лесенку — единственный вариант из двух, который буквально совпадает с механикой
  реализованного алгоритма (сначала все двойки, потом возрастающие нечётные делители), а не
  просто иллюстрирует общую идею «разложить на множители». Трассировка: MUST-form-before-name.
- **F10** (прямой запрос пользователя: «мемори-банк не должен содержать конкретные задачи»)
  `specs/euler001.md`/`euler002.md`/`euler003.md` и блоки `[euler::*]` в `_terms.md` хранили
  условие/критерии корректности конкретных задач — переиспользуемым знанием это не является,
  задача с решением уже проверена реальным сабмитом один раз. Удалены. Промежуточный шаг — поле
  `Used in:` стало настоящей ссылкой вместо голого текста — оказался неполным: см. F11.
- **F11** (следующий вопрос пользователя: «здесь же только базовые примитивы, не?») Само поле
  `Used in:`, даже как ссылка, — тоже упоминание конкретной задачи в файле, который должен быть
  про задачи вообще молчать. Удалено из всех записей полностью; связь однонаправленная — задача
  ссылается на примитив из своего README, каталог о задаче не знает ничего. Трассировка:
  MUST-no-task-specifics (ужесточено).

## Architecture

### Обзор (прозой)
Три раздельных источника, сборка — скрипт: общий каркас страницы ([viz::PageSkeleton](../_terms.md#vizpageskeleton),
`visualizations/skeleton.html`), описание приёма (блок `[viz::*]` в `memory-bank/_terms.md`: что
это, откуда, применимость, границы, ссылка на подход, картинка), код кадров
(`visualizations/examples/<slug>.{css,html,js}`). `visualizations/build.sh` подставляет код в
каркас → `build/<slug>.html`, затем headless-браузер (светлая тема, ширина 720, высота по
измеренной карточке) → `build/<slug>.png`; png вставлен в блок термина полем `Picture:`. Навык
находит блок → запускает `build.sh <slug>` → смотрит png → открывает html. Никакого рендера «на
глаз», никакого облака, никаких картинок руками.

### Bounded Contexts и Aggregate Roots
- `viz` — [viz::Catalog](../_terms.md#vizcatalog) (root): Card, Frame; [viz::PageSkeleton](../_terms.md#vizpageskeleton) (VO).
- `approach` — [approach::Collection](../_terms.md#approachcollection) (root) — соседний контекст, связь через явные ссылки в
  обе стороны, не через общее поле.

## Requirements
> Формулировка — критерий приёмки — статус.

### MUST
- Визуальная форма приёма MUST выбираться по понятности с первого взгляда человеку без
  подготовки; стандартное название ищется ПОСЛЕ выбора формы и именно для неё —
  **MUST-form-before-name** — критерий: в карточке поля `Standard name:` и `Source:` относятся к
  той форме, что нарисована, а не к родственнику с другой целью. Статус: реализовано (skip
  counting, bar model, Gauss pairing, Venn, binary search, ladder method).
- Картинка MUST быть последовательностью кадров: первый — Problem (нерешённая ситуация, помечена
  как неверная/неизвестная), последний — Solution, между ними один и более Transform —
  **MUST-frame-sequence** — критерий: поле `Sequence:` спека и разметка `examples/<slug>.html`
  содержат те же кадры в том же порядке; одиночный статичный кадр — нарушение. Статус:
  реализовано (6/6).
- Подписи на картинке MUST быть символьными метками (`?`, `×2`, `−`, `⌒`, `∩`, `=`), MUST NOT
  быть предложениями — **MUST-symbolic-labels** — критерий: в `examples/<slug>.html` внутри
  `frame-tag` нет текста длиннее одного символа/короткого токена. Статус: реализовано.
- Всё, что нужно читать (описание, применимость, границы, источник), MUST жить в спеке, не под
  картинкой — **MUST-text-in-spec** — критерий: в собранной странице под `.flow` нет абзацев,
  только ссылка на спек. Статус: реализовано.
- «Готово» MUST NOT объявляться, пока результат отрисовки не наблюдался (скриншот/зум); подсчёт
  тегов MUST NOT считаться проверкой картинки — **MUST-render-observed** — критерий: перед показом
  владельцу есть шаг наблюдения; владелец не является первым, кто увидел картинку. Статус:
  частично — `build.sh` всегда производит png, навык требует его прочитать (шаги 3/4e);
  механической блокировки показа без просмотра нет (в сессии-источнике нарушено 4 раза; при
  первом прогоне `build.sh` просмотр png сразу поймал обрезанную подпись у Гаусса и тёмную тему).
- Геометрия наложений (дуги, стрелки, подписи над элементами) MUST измеряться у отрисованных
  элементов, MUST NOT вычисляться из предполагаемых CSS-размеров — **MUST-geometry-measured** —
  критерий: `examples/*.js` берут координаты через `getBoundingClientRect`, констант ширины ячеек
  в вычислениях нет. Статус: реализовано (skip-counting.js, gauss-pairing.js).
- Все промежуточные числа примера MUST быть различимы между шагами — **MUST-distinct-step-numbers**
  — критерий: список чисел всех кадров не содержит совпадений по разным причинам (30 как площадь
  и 30 как итог — нарушение). Статус: реализовано (Gauss: 4..20, пары 24, итог 60).
- Поле применимости MUST описывать класс задач, MUST NOT пересказывать параметры примера —
  **MUST-applicability-is-class** — критерий: формулировка не исключает ни одного случая, который
  приём реально берёт; параметры примера, если они ограничивают, идут в `Limits` с пометкой
  «предел рисования, не приёма». Статус: реализовано.
- Границы применимости MUST называть настоящую причину предела — **MUST-limits-are-causal** —
  критерий: нет формулировок вида «становится тесно / путает глаз»; есть механизм (три условия не
  выстраиваются в один ряд; четыре круга доказуемо не покрывают пересечения). Статус: реализовано.
- Исправление формулировки в одной карточке MUST проверяться на всех остальных сразу —
  **MUST-fix-propagates** — критерий: правка класса ошибки закрывается одним раундом, не по
  карточке за замечание. Статус: процессное, PASSIVE.
- Повторная сборка приёма MUST давать байт-в-байт ту же картинку — **MUST-deterministic-rebuild**
  — критерий: страница собирается копированием каркаса + `examples/<slug>.*`; ни одно число, цвет
  или класс не живёт вне версионированных файлов. Статус: реализовано.
- Код кадров MUST храниться отдельно от спека, спек ссылается на него полем `Example:` —
  **MUST-code-separate** — критерий: в блоке `[viz::*]` нет кода, только поле `Example:` с путями; `examples/<slug>.{css,html,js}`
  существуют и совпадают с тем, что вставляет навык. Статус: реализовано.
- Каждая карточка MUST нести поле `Approach:` — ссылку на запись [approach::Collection](../_terms.md#approachcollection) либо
  явное «—» с причиной — **MUST-approach-link** — критерий: `grep '^Approach:'` даёт строку в
  каждом блоке `[viz::*]`; для skip-counting — «—, показывает понятие "кратно", не способ счёта».
  Статус: реализовано.
- Сквозной пример MUST быть один на каталог («числа до 20, кратные 2 или 3») и MUST NOT совпадать
  с числами конкретной задачи — **MUST-shared-example** — критерий: ни в одной карточке нет 3 и
  5 из euler001; новый приём, несовместимый с примером, заводит свой и объясняет почему. Статус:
  реализовано.
- Файл-редирект со старого имени MUST оставляться только при наличии входящих ссылок; без них
  старый файл удаляется — **MUST-redirect-only-if-linked** — критерий: перед выбором выполнен
  `grep` по старому имени. Статус: реализовано (три стуба удалены после grep).
- Каждая собранная страница и каждый png MUST нести QR-код на репозиторий
  (`https://github.com/Hedgehogues/project-euler`) и адрес текстом — картинку пересылают отдельно
  от текста, путь к исходникам должен быть на ней самой — **MUST-qr-repo-link** — критерий: QR —
  блок каркаса `skeleton.html` (`.repo`), не приёма; `build.sh` падает без
  `visualizations/qr-repo.svg`; после генерации QR декодирован из собранного png и даёт ровно
  этот URL. Статус: реализовано.
- Текст карточек и спеков MUST NOT упоминать детей/школу как адресата — уровень простоты
  задаётся требованием, не аудиторией — **MUST-no-audience-mention** — критерий: `grep -i
  'дет|школ|садик'` по каталогу пуст. Статус: реализовано.
- Каталог MUST NOT хранить НИЧЕГО о конкретной задаче — ни условие, ни решение, ни критерии
  корректности, ни обратную ссылку «использовано в» — **MUST-no-task-specifics** — критерий: в
  `memory-bank/` нет `specs/euler{NNN}.md`, блоков `[euler::*]` и поля `Used in:`; связь только
  однонаправленная — задача в своём README ссылается на блок здесь по имени. Статус: реализовано
  (найдено в два приёма — F10, затем F11).

### SHALL
- Навык-сборщик SHALL читать `index.md` первым шагом каждого вызова и SHALL NOT полагаться на
  память о прошлом вызове — **SHALL-index-first**. Статус: реализовано (SKILL.md, шаг 1).
- Новый приём SHALL проходить полный цикл (поиск стандартного названия → сквозной пример →
  `Sequence` → спек + `examples/` → строка индекса) ДО показа владельцу — **SHALL-full-cycle-before-show**.
  Статус: реализовано (SKILL.md, шаг 4).
- Неоднозначное сопоставление запроса с 2+ карточками SHALL решаться вопросом владельцу, не
  угадыванием — **SHALL-ask-on-ambiguity**. Статус: реализовано (SKILL.md, шаг 5).

### SHOULD
- Шаг наблюдения рендера (MUST-render-observed) SHOULD быть механизирован в навыке как
  обязательный скриншот-шаг, а не прозой — **SHOULD-mechanize-render-check**. Статус: не
  реализовано.
- Проверка различимости чисел (MUST-distinct-step-numbers) SHOULD выполняться по списку чисел в
  спеке, а не глазами — **SHOULD-number-list-check**. Статус: не реализовано.
