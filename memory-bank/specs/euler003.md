# euler003 — Largest prime factor

## Vision
For each of `T` given values of `N`, find the largest prime factor of `N`. `N` can be large
enough (up to ~6·10^11 in the classic Project Euler statement) that factoring by checking every
integer up to `N` is out of the question — the algorithm must strip out small factors as it goes
so the remaining number shrinks fast, keeping the trial range near `sqrt(N)`.

## Термины
MUST/MUST NOT/SHALL/SHOULD/SHOULD NOT/MAY — как в RFC 2119. Термин задачи:
[euler::Problem003](../_terms.md#eulerproblem003). Использует один каталогизированный подход:
[approach::TrialDivision](../_terms.md#approachtrialdivision).

## Скоуп

## Architecture

### Обзор (прозой)
[approach::TrialDivision](../_terms.md#approachtrialdivision): сначала выносится весь множитель
2 (пока число чётное — делим), затем перебираются только нечётные делители `p = 3, 5, 7, ...`, и
каждый раз, пока `n` делится на `p`, `p` выносится из `n`. Перебор останавливается, когда
`p·p > n` — если после этого `n > 1`, само `n` — простое и оно больше любого уже вынесенного
делителя (перебор шёл по возрастанию), значит это и есть наибольший простой множитель. Если
`n == 1`, наибольший вынесенный делитель уже и есть ответ. Ключевое свойство, которое делает
перебор быстрым: как только делитель вынесен, `n` УМЕНЬШАЕТСЯ, так что граница `p·p ≤ n` сама
падает по ходу дела — перебор никогда не доходит до `sqrt` исходного `N`, если у числа есть
маленькие множители.

### Данные
- Вход: `T`, затем `T` строк с `N`.
- Выход: `T` строк — наибольший простой множитель `N`, на строку.

## Requirements
> Формулировка — критерий приёмки — статус.

### MUST
- `largestPrimeFactor(n)` MUST совпадать с независимым перебором «для каждого `d` от 2 до `n`
  проверить простоту и делимость» для характерных и граничных `n` (2, 3, 4, 6, 13195, 997,
  999983, 600851475143) — **MUST-match-bruteforce** — критерий: разница нулевая на всём
  проверенном диапазоне, включая классический пример Project Euler (`13195 → 29`) и полное `N`
  оригинальной задачи (`600851475143 → 6857`). Статус: реализовано (Accepted 100% на HackerRank,
  submission 1410850859, 2026-07-12; независимо перепроверено брутфорсом на `n=2..20000` и на
  этих контрольных точках).
- Перебор делителей MUST останавливаться по условию `p·p ≤ n` (где `n` — то, что ОСТАЛОСЬ после
  уже вынесенных делителей, не исходное `N`), не идти до `sqrt(N)` вслепую —
  **MUST-shrink-bound** — критерий: условие цикла `p * p <= n`, `n` переприсваивается после
  каждого деления внутри того же цикла. Статус: реализовано.
- Множитель 2 MUST выноситься отдельным циклом до основного перебора нечётных делителей —
  **MUST-strip-two-first** — критерий: `while (n % 2 == 0)` предшествует циклу `for (p = 3; ...;
  p += 2)`; последующий перебор идёт только по нечётным `p`. Статус: реализовано.
- Если после перебора делителей осталось `n > 1`, оно MUST считаться самим по себе простым
  множителем (и, значит, ответом, раз перебор шёл по возрастанию) — **MUST-remainder-is-prime**
  — критерий: `if (n > 1) largest = n;` после цикла. Статус: реализовано.
- `solution.cpp` MUST быть чистым ASCII — **MUST-ascii-only** — критерий:
  `grep -nP '[^\x00-\x7F]' solution.cpp` пуст. Статус: реализовано.
- Ввод-вывод MUST соответствовать формату HackerRank — **MUST-io-format**. Статус: реализовано.
