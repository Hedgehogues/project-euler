# Метод объяснения: требования к ИДЕЕ

## Vision
Объясняя решение задачи человеку, называть не формулу, а идею за ней — так, чтобы по признакам в
условии следующей задачи ту же идею можно было узнать заранее. Каталог копится по мере разбора
решённых задач, но сам НЕ хранит ни одной задачи и ни одной ссылки на задачу — только чистые
идеи, как в учебнике.

Этот спек и соседний [visualizations](visualizations.md) описывают ОДИН И ТОТ ЖЕ набор записей
`[method::*]` в `_terms.md` с двух сторон: здесь — требования к идее (атомарность, узнаваемость,
источник), там — к её картинке (кадры, сборка, наблюдение рендера). Это не два каталога — это
два аспекта одного.

## Термины
MUST/MUST NOT/SHALL/SHOULD/SHOULD NOT/MAY — как в RFC 2119. Термины — `_terms.md`, контекст
`method`: [method::Catalog](../_terms.md#methodcatalog),
[method::SkipCounting](../_terms.md#methodskipcounting),
[method::InclusionExclusion](../_terms.md#methodinclusionexclusion),
[method::VennDiagram](../_terms.md#methodvenndiagram),
[method::ArithmeticProgressionSum](../_terms.md#methodarithmeticprogressionsum),
[method::Precomputation](../_terms.md#methodprecomputation),
[method::BinarySearch](../_terms.md#methodbinarysearch),
[method::TrialDivision](../_terms.md#methodtrialdivision).

## Скоуп
**В скоупе:** поля идеи в блоках `[method::*]` (`Essence` / `Recognized by` / `General case` /
`Limits` в части идеи / `Source`), дисциплина «атом или названная композиция», дисциплина
пополнения.

**Вне скоупа:** поля картинки в тех же блоках (`Picture` / `Sequence` / `Example` / `Limits` в
части рисунка) — см. [visualizations](visualizations.md); `TRICKS.md` в корне репозитория —
приёмы УСКОРЕНИЯ вычисления, найденные в исследовательском процессе, со своей цитатной
дисциплиной; сами задачи (условие, решение, критерии корректности) — живут в
`euler{NNN}/README.md`, не здесь (см. MUST-no-task-specifics).

## Находки, положенные в основу
- **F1** Коллекция подходов и каталог картинок существовали параллельно без ссылок; при связывании
  выяснилось: подходов без картинки нет, а картинка без подхода одна (счёт прыжками —
  понятие, не способ счёта). Трассировка: MUST-picture-optional, MUST-no-invented-approach.
- **F2** Первая формулировка включения-исключения была «А+Б−АБ» — частный случай двух условий,
  выданный за общий. Трассировка: MUST-general-case.
- **F3** (euler002) Признак «предвычислить один раз + бинарный поиск на запрос» легко спутать с
  самим предвычислением — у предвычисления нет своей визуализации (тот же класс, что счёт
  прыжками для «кратно», F1); отдельная, безусловно стандартная техника — сам бинарный поиск.
  Трассировка: MUST-picture-optional, MUST-no-invented-approach.
- **F4** (euler002, найдено прямым вопросом пользователя «точно по 1 подходу?») F3 смешала два
  разных вопроса — «нужна ли этому шагу отдельная КАРТИНКА» (нет — предвычисление не рисуется, F1)
  и «нужна ли этому шагу отдельная ЗАПИСЬ» (это не то же самое: у обеих идей задачи 1 —
  включение-исключение и сумма прогрессии — своя литература, они узнаются в разных задачах порознь;
  предвычисление и бинарный поиск — тоже). Единый блок `PrecomputeAndBinarySearch` был неверно
  слеплен из-за этой путаницы. Разделён на
  [method::Precomputation](../_terms.md#methodprecomputation) (без картинки — честно помечено, не
  выдумано) и [method::BinarySearch](../_terms.md#methodbinarysearch) (с картинкой). Трассировка:
  MUST-entry-independent-of-picture.
- **F5** (прямой запрос пользователя: «1 подход — 1 картинка», «мемори-банк не должен содержать
  конкретные задачи», «должны быть ссылки на стандартные подходы»). Три находки одним проходом:
  1. Включение-исключение нарушало «1 картинка на запись» — имело ДВЕ (полоска и диаграмма Венна).
     Разбор показал, что это НЕ одна идея дважды нарисованная, а две разные, независимо
     стандартные идеи, часто используемые вместе (тот же паттерн, что F4): включение-исключение —
     арифметика подсчёта; диаграмма Венна — представление логических утверждений кругами,
     изобретена Джоном Венном в 1880 для СОВСЕМ ДРУГОЙ цели (не для счёта). Разделены; обе
     картинки сохранены, каждая при своей записи.
  2. Ни одна идея не несла поля `Source:` — независимые ссылки были только у картинок. Добавлено.
     Трассировка: MUST-source.
  3. `euler001.md`/`euler002.md`/`euler003.md` жили как отдельные спеки ВНУТРИ memory-bank —
     конкретные задачи, не переиспользуемое знание. Удалены. Трассировка: MUST-no-task-specifics.
- **F6** (вопрос пользователя после F5: «здесь же только базовые примитивы?») Оставшееся поле
  `Used in: [euler001](...)` — тоже упоминание конкретной задачи, и оно же требовало бы правки
  ЭТОГО файла при переименовании задачи, дублируя связь, целиком видную с другой стороны. Удалено
  полностью; связь строго однонаправленная — из задачи в примитив. Трассировка:
  MUST-no-task-specifics (ужесточено), MUST-reuse-changes-nothing.
- **F7** (вопрос пользователя «опять дубли есть», подтверждённый grep'ом по файлу) Разделение на
  два контекста — `[approach::*]` (идея) и `[viz::*]` (картинка) — само оказалось дублированием:
  два блока с ОДИНАКОВЫМИ именами (`VennDiagram`, `BinarySearch`), каждая из пяти картинок
  вставлена дважды, источники продублированы, описания — пересказ друг друга. Ранее это
  защищалось доводом «это разные слои» (F4/F5 разводили идеи именно по этой логике) — довод был
  неверен: слои различимы ПОЛЯМИ внутри одной записи, а не двумя списками. Контексты объединены в
  один `method`; поля идеи и картинки живут в одном блоке, `Limits` помечает, где предел идеи, а
  где только рисунка. Трассировка: MUST-single-entry-per-method.

## Architecture

### Обзор (прозой)
Блоки `[method::*]` в `memory-bank/_terms.md`, по блоку на метод. Поля идеи: Essence (одна фраза
без формул) / Recognized by (признаки в условии) / General case (не для конкретных чисел) /
Source (независимая ссылка на стандартность) / Limits (в части идеи). Ни одного поля про
конкретную задачу. Каждая запись — либо атомарная идея, либо явно названная композиция
атомарных. Пополняется при разборе задачи; повторное применение известного метода не меняет этот
файл вообще — задача в своём README ссылается на существующий блок.

### Bounded Context и Aggregate Root
- `method` — единственный контекст; [method::Catalog](../_terms.md#methodcatalog) (root),
  [method::PageSkeleton](../_terms.md#methodpageskeleton) (VO), остальные блоки — entities.
  Отдельного контекста для картинок нет (см. F7) — картинка это поля записи метода.

## Requirements
> Формулировка — критерий приёмки — статус.

### MUST
- Один метод MUST описываться ОДНОЙ записью `[method::*]`; идея и её картинка MUST NOT
  разноситься по двум параллельным блокам/контекстам — **MUST-single-entry-per-method** —
  критерий: `grep -oE '^## \[\w+::\w+\]' _terms.md` даёт только контекст `method`, и среди имён
  нет повторов (`... | sort | uniq -d` пуст); каждая картинка `build/*.png` упомянута в файле
  ровно один раз. Статус: реализовано (найдено пользователем — F7).
- Каждая запись MUST содержать поля Essence / Recognized by / General case / Source (плюс поля
  картинки, когда она есть), MUST NOT содержать поле про конкретную задачу —
  **MUST-entry-schema** — критерий: `grep` по каждому обязательному заголовку даёт столько строк,
  сколько записей-методов (7); поля `Used in:` в файле нет. Статус: реализовано.
- «Essence» MUST быть одной фразой без формул — **MUST-essence-plain** — критерий: в поле нет
  `·`, `/`, степеней, обозначений переменных. Статус: реализовано.
- «General case» MUST описывать идею для произвольных параметров, MUST NOT выдавать частный
  случай за общий — **MUST-general-case** — критерий: для включения-исключения назван случай k
  условий, «А+Б−АБ» помечен как k=2. Статус: реализовано.
- «Recognized by» MUST называть признаки в ТЕКСТЕ УСЛОВИЯ, по которым метод виден до решения —
  **MUST-recognition-trigger** — критерий: признак формулируется как наблюдение над условием
  («в условии есть "или"», «нужна сумма, а не количество»), не как свойство решения. Статус:
  реализовано.
- Каждая запись MUST нести своё поле `Source:` — независимую ссылку на то, что идея стандартна;
  когда у картинки свой отдельный источник, он идёт в том же поле с пометкой «картинка:» —
  **MUST-source** — критерий: `grep -c '^Source:'` равен числу записей-методов. Статус:
  реализовано (7 из 7).
- У записи MUST быть не больше одной картинки — **MUST-one-picture-max** — критерий: в блоке не
  больше одного поля `Picture:` и не больше одной ссылки на `build/*.png`. Идея с двумя
  независимо стандартными визуальными формами — это две записи (см. F5.1), а не одна с двумя
  портретами. Статус: реализовано.
- Отсутствие картинки MUST NOT решать, заводить ли отдельную запись — это два разных вопроса:
  «узнаётся ли идея отдельно от соседних» (решает запись) и «есть ли устоявшийся визуальный
  образ» (решает картинку) — **MUST-entry-independent-of-picture** — критерий:
  [method::Precomputation](../_terms.md#methodprecomputation) — легитимная запись с `Picture: —`,
  рядом с [method::BinarySearch](../_terms.md#methodbinarysearch), у которого картинка есть.
  Статус: реализовано (найдено пользователем — F4).
- Запись без картинки MUST помечать это явной причиной, а не пустым полем —
  **MUST-picture-optional** — критерий: значение `Picture: —` сопровождается объяснением, почему
  образа нет. Статус: реализовано.
- Метод MUST NOT заводиться под существующую картинку ради симметрии —
  **MUST-no-invented-approach** — критерий: картинка, у которой нет самостоятельной идеи, не
  порождает запись; счёт прыжками — не такой случай (это самостоятельный метод: так определяется
  кратность). Статус: реализовано.
- Каждая запись MUST быть либо атомарной (одна неделимая идея), либо явно названной композицией
  из 2+ атомарных, MUST NOT быть «атом + неназванный довесок» — **MUST-atomic-or-composed** —
  критерий: если решение использует 2+ независимо стандартные идеи, каждая получает свою запись
  (как `Precomputation`+`BinarySearch`, `InclusionExclusion`+`VennDiagram`). Статус: реализовано.
- Каталог MUST NOT хранить НИЧЕГО о конкретной задаче — ни условие, ни решение, ни критерии
  корректности, ни обратную ссылку «использовано в» — **MUST-no-task-specifics** — критерий: в
  `memory-bank/` нет `specs/euler{NNN}.md`, блоков `[euler::*]` и поля `Used in:`. Статус:
  реализовано (в два приёма — F5.3, затем F6).
- Повторное применение известного метода к новой задаче MUST NOT менять этот файл —
  **MUST-reuse-changes-nothing** — критерий: `git diff` на `_terms.md` пуст при добавлении
  задачи, использующей уже описанный метод; ссылка появляется только в `euler{NNN}/README.md`.
  Статус: реализовано.

### SHOULD
- Название метода SHOULD быть общепринятым (проверенным поиском) — **SHOULD-standard-name**.
  Статус: реализовано для всех семи (каждое сверено поиском до записи).
